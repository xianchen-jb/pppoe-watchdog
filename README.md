[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![Platform](https://img.shields.io/badge/platform-Windows%2010%20%7C%2011-0078D6.svg)](#)
[![PowerShell](https://img.shields.io/badge/PowerShell-5.1%2B-blue.svg)](#)
[![Dependencies](https://img.shields.io/badge/dependencies-none-brightgreen.svg)](#)

> 开机、唤醒、掉线之后自动把 PPPoE 宽带连回来 —— 把「每次都要手动点一下宽带连接」这件事彻底消灭。

这是我给自己学校有线校园网写的一个小工具。它常驻在后台，靠「探测公网 + 会话状态」两个信号判断网络是否活着，一旦发现断了就自己重拨，全程不需要人管。

---

## 它解决什么问题

学校的有线网是**标准 Windows PPPoE 拨号**（不是锐捷 / Dr.COM 那类客户端），这意味着：

1. **每次开机都要手动拨一次** —— 登录桌面之后还得再去点「宽带连接」。
2. **睡眠 / 合盖之后连接必掉** —— 醒了还得再拨一次。
3. **偶尔莫名其妙掉线** —— 可能过了十几分钟才发现网没了。

这三个场景手动操作加起来一天要重复十几次，所以干脆让程序替我盯着。

## 实测效果

| 场景 | 优化前 | 优化后 | 数据来源 |
| --- | --- | --- | --- |
| 意外掉线自愈 | 36 秒 | **4 秒** | 实测日志：`17:28:11` 疑似掉线 → `17:28:15` 已连上 |
| 睡眠唤醒后恢复 | 49 秒 | 约 20 秒 | 49 秒为实测；20 秒是按新探测耗时推算 |
| 开机到有网 | 约 40 秒 | 约 20 秒 | 40 秒由日志各阶段耗时推算；20 秒待下次冷启动验证 |
| 单次连通性探测 | 8.5 秒 | 0.5 ~ 1.2 秒 | 实测 |

常驻开销：工作集约 80 ~ 150 MB（波动），CPU 约单核 0.26%。

## 工作原理

```
         ┌──────────────────────────────┐
         │  计划任务 PppoeWatchdog       │
         │  登录时触发 · 最高权限 · 单实例 │
         └──────────────┬───────────────┘
                        │
              ┌─────────▼─────────┐
              │   读 config.json   │
              │  + cred.dat(DPAPI) │
              └─────────┬─────────┘
                        │
              ┌─────────▼─────────┐
              │ 快速通道：会话在吗？ │
              └────┬─────────┬────┘
              不存在│         │存在
                   ▼         ▼
            ┌──────────┐  ┌──────────┐
            │ 等链路就绪 │  │ 不打扰   │
            │ → 直接拨号 │  │ 进主循环 │
            └────┬─────┘  └────┬─────┘
                 └──────┬──────┘
                        ▼
        ┌───────────────────────────────┐
        │ 主循环：每 10s 探测一次公网     │
        │  (3 个目标，任一可达即正常)     │
        └───────────────┬───────────────┘
                        │ 不通
                        ▼
        ┌───────────────────────────────┐
        │ 1s 后复检 → 连续 2 次不通即确认 │
        │ → 等链路 → rasdial 重拨         │
        │ → 失败则退避 15s 起翻倍至 300s  │
        └───────────────────────────────┘
```

关键参数（全部可在脚本开头改，脚注见 `docs/使用手册.md`）：

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `$ProbeList` | `223.5.5.5`, `119.29.29.29`, `180.76.76.76` | 探测目标，任一可达即算正常 |
| `$ProbeTimeoutMs` | `600` | 单个 ping 超时，这是「发现掉线有多快」的关键 |
| `$Interval` | `10` | 健康状态下的轮询间隔（秒） |
| `$FailThresh` | `2` | 连续几次不通才判定掉线 |
| `$RecheckDelay` | `1` | 判定不通后的快速复检间隔 |
| `$RetryDelay` / `$RetryMax` | `15` / `300` | 重拨失败的退避起点与上限 |

## 快速开始

**要求**：Windows 10 / 11，已存在一个能正常工作的 PPPoE 拨号连接，PowerShell 5.1（系统自带）。

1. 把 `scripts/` 里全部文件放到任意固定目录（例如 `C:\Tools\pppoe`）。批处理用的是 `%~dp0`，放在哪都行，但**放好之后不要再挪**，否则计划任务会失效。
2. 双击 **`setup.bat`** —— 输入连接名、宽带账号、密码。密码用 DPAPI 加密后存到 `%LOCALAPPDATA%\PppoeWatchdog\cred.dat`，明文不落盘。
3. 双击 **`install.bat`** —— 注册计划任务（登录时触发、最高权限），并立刻启动守护进程。UAC 会弹一次。
4. 双击 **`check.bat`** —— 随时查看自检结果和最近日志。

想调整网卡的省电策略（会影响链路速率和唤醒后的重连速度）：

- `tune-nic.bat` —— **只预览**，列出哪些设置会被改、当前值是什么。
- `tune-nic-apply.bat` —— 真正写入（需要管理员，会让链路重新协商几秒）。

卸载：`uninstall.bat`。

## 几个设计上的取舍

**为什么用「轮询探测」而不是「靠系统电源事件唤醒」**

原本想监听 `Kernel-Power` / `Power-Troubleshooter` 事件来触发重拨，但这台机器只有 **Modern Standby（S0 低电量待机）**，没有传统 S3，睡眠进出的事件 ID 和顺序跟文档里写的不一致，容易漏触发。改成常驻轮询之后，不管是睡眠唤醒、网线松了、还是运营商把你踢下线，走的是同一条恢复路径，**一套逻辑覆盖所有掉线原因**，反而更稳。

**为什么探测不用 `Test-Connection`**

实测 `Test-Connection -Count 2` 打一个不可达地址要**干等 8.5 秒**才返回。换成 .NET 的 `System.Net.NetworkInformation.Ping` 并把超时设成 600ms 之后，单次探测降到 0.5 秒左右。这一个改动就把「发现掉线」的时间从 36 秒压到了 4 秒，是整个优化里性价比最高的一处。

**为什么要做「快速通道」**

刚开机时 PPPoE 会话肯定不存在，没必要先探测两次再确认掉线（白等 5 秒）。所以守护启动时先查一次会话：不存在就直接拨号。关键是**只在会话确实不存在时才走捷径** —— 睡眠唤醒时会话是「存在但已失效」，仍然交给正常循环判断，不会误伤一条本来好着的连接。

**为什么密码不用 Windows 凭据管理器**

`rasdial` 本身就要求每次传明文密码。用 DPAPI（`ConvertFrom-SecureString` + 用户作用域）存到 `cred.dat`，只有当前 Windows 用户能解开，比明文存配置文件安全，也比反复弹窗输密码实用。

## 已知限制

这几条是原理上就绕不过去的，写在这里免得以后自己困惑：

- **睡眠期间不可能保持在线**。这台机器没有 S3，只有 Modern Standby；PPPoE 是用户会话内的会话，睡眠时必然中断。能在「醒来后多快连回来」上优化，但做不到「不断」。
- **必须先登录 Windows 才能拨号**。PPPoE 会话由 RasMan 在用户会话里维护，SYSTEM 身份的服务拨不了。所以计划任务用的是「登录时触发 + 交互式用户」，而不是开机即跑的服务。
- **`rasdial` 的密码会短暂出现在命令行里**。这是它自带的缺陷，同机其他进程理论上能抓到。个人机器可接受，多用户环境要慎重。
- **探测用的是 ICMP**。部分网络会屏蔽 ping，那种环境下需要把 `$ProbeList` 换成能通的 TCP 目标（脚本目前只实现 ICMP）。
- **快速启动（Fast Startup）会让网卡状态带病跨重启**。`tune-nic.ps1` 会把它关掉，这也是「开机后链路要等好几秒」的原因之一。

## 踩坑记录

整个过程踩了十几个坑，包括几个不查就绝对想不到的：

- `powercfg /a` 发现机器根本没传统睡眠，之前所有「配网卡唤醒」的设想全部作废
- `Get-NetAdapterPowerManagement` 直接报 `系统错误 31`，因为 Realtek 驱动不暴露那个 WMI 类
- PowerShell 5.1 按 GBK 解析无 BOM 的 UTF-8 脚本，中文全变乱码
- 计划任务设了 `IgnoreNew`，改完代码旧进程一直占着，**新代码根本没生效**
- 按关键字杀进程时把自己的 shell 一起杀了
- 健康判定把「网卡状态」和「公网可达」混在一起，刚唤醒时误报掉线

完整的过程、排查思路和解决办法写在 **[docs/遇到的问题与解决.md](docs/遇到的问题与解决.md)**，一共 17 条。如果你也想给自己的校园网做类似的东西，那份文档比脚本本身更值得看。
