# 使用手册

面向「装好之后日常怎么用、怎么调」的操作细节。项目背景和设计取舍见 [README](../README.md)。

---

## 一、部署前的环境确认

脚本本身不挑环境，但下面几项直接决定**能不能用**、以及**哪些优化对你有效**。装之前先花两分钟确认。

| 检查项 | 怎么看 | 期望结果 |
| --- | --- | --- |
| 拨号方式 | 控制面板 → 网络连接，看是否有「宽带连接」这类 PPPoE 拨号项 | 存在即可。本工具只支持 **Windows 原生 PPPoE**（`rasdial`），不支持锐捷 / Dr.COM 等第三方客户端 |
| 睡眠能力 | `powercfg /a` | 有 S3 更好；只有 `待机 (S0 低电量待机)` 也能用，但睡眠期间无法保持在线 |
| PowerShell | `$PSVersionTable.PSVersion` | 5.1 或以上（系统自带即可） |
| 管理员权限 | —— | 安装和网卡调整需要，配置账号密码不需要 |

> **关于第三方客户端**：如果你的校园网必须用锐捷、Dr.COM、哆点之类的客户端认证，本工具**用不上** —— 那些客户端走的是私有协议，不是标准 PPPoE。可以先用 `rasdial` 手动试一次：能拨通说明是标准 PPPoE。

## 二、安装（三步）

先把 `scripts/` 里的全部文件放到一个固定目录（例如 `C:\Tools\pppoe`）。批处理用的是 `%~dp0`（相对自身路径），**放哪里都行，但装完别挪**，否则计划任务会指向失效路径。

### 第 1 步：配置账号密码

双击 **`setup.bat`**，按提示输入：

- **连接名** —— 直接回车即用默认的 `宽带连接`。不确定的话去「控制面板 → 网络连接」看那个拨号项叫什么。
- **宽带账号**
- **宽带密码**

密码用 **DPAPI**（Windows 数据保护 API，用户作用域）加密后写到：

```
%LOCALAPPDATA%\PppoeWatchdog\cred.dat
```

只有当前 Windows 用户能解开。脚本文件、配置文件里都**不含明文密码**。

### 第 2 步：注册计划任务

双击 **`install.bat`**，会弹一次 UAC 请求管理员权限，然后：

- 注册名为 `PppoeWatchdog` 的计划任务
- 触发器：**用户登录时**，延迟 5 秒
- 以最高权限、交互式用户身份运行
- 单实例（互斥体 `Local\PppoeWatchdog`），不会起两份
- 失败后每 1 分钟自动重启，不限运行时长，电池供电下也运行
- 立即启动一次，并打印新守护进程的 PID

### 第 3 步：验证

双击 **`check.bat`**，正常应看到：

```
连接名        : 宽带连接
账号          : 已配置
密码          : 已读取（DPAPI）
以太网链路    : Up
PPPoE 会话    : Internet
公网连通      : 正常
守护进程      : 运行中
计划任务      : 已注册·Running
```

然后合盖等一两分钟再打开，过约 20 秒再跑一次 `check.bat`，仍显示「正常」就说明唤醒重拨生效了。

也可以直接看日志：

```
%LOCALAPPDATA%\PppoeWatchdog\watchdog.log
```

## 三、文件说明

| 文件 | 作用 |
| --- | --- |
| `pppoe-watchdog.ps1` | 守护主脚本。`-Setup` 配置向导，`-Check` 自检，无参数进守护循环 |
| `setup.bat` | 配置向导入口 |
| `install.ps1` / `install.bat` | 注册并启动计划任务（自动提权） |
| `uninstall.ps1` / `uninstall.bat` | 停止守护、删除计划任务 |
| `check.bat` | 单次自检，随时可跑 |
| `tune-nic.ps1` / `tune-nic.bat` | 网卡省电特性调整，**默认只预览** |
| `tune-nic-apply.bat` | 同上，但**真正写入**（需管理员，会短暂断网） |

运行时文件都在 `%LOCALAPPDATA%\PppoeWatchdog\`：`config.json`（连接名等）、`cred.dat`（DPAPI 加密的密码）、`watchdog.log`。

## 四、可调参数

改 `pppoe-watchdog.ps1` 开头这一段：

```powershell
$ProbeList      = @('223.5.5.5', '119.29.29.29', '180.76.76.76')  # 探测目标，任一可达即算正常
$ProbeTimeoutMs = 600        # 单个 ping 的超时（毫秒）
$Interval       = 10         # 健康状态下的轮询间隔（秒）
$FailThresh     = 2          # 连续异常几次后触发重拨
$RecheckDelay   = 1          # 判定不通后的快速复检间隔（秒）
$LinkTimeout    = 60         # 等待以太网链路 Up 的最长时间（秒）
$RetryDelay     = 15         # 重拨失败后的退避起始值（秒）
$RetryMax       = 300        # 退避上限（秒）
```

几个调整思路：

| 想要 | 改什么 |
| --- | --- |
| 发现掉线更快 | 调小 `$Interval` 和 `$ProbeTimeoutMs`（注意耗电和 CPU） |
| 不想要误报 | 调大 `$FailThresh`（代价是恢复变慢） |
| 探测目标被墙了 | 换 `$ProbeList`；只支持 ICMP，需要 TCP 探测得自己改 `Test-Online` |
| 开机更快 | `install.ps1` 里的 `$trigger.Delay`（当前 `PT5S`），不建议低于 3 秒 |

`$ProbeTimeoutMs` 是「发现掉线有多快」的关键：改用 .NET `Ping` 配 600ms 超时后，单次探测从 8.5 秒降到约 0.5 秒，掉线确认从 36 秒压到约 4 秒。

**改完必须让新代码真的生效。** 双击 `install.bat` 重新注册是最省事的 —— 它会先停掉旧的守护进程、等它退出，再启动新的，最后打印新 PID。只看文件修改时间不算数：计划任务是单实例的，旧进程不退出，新的根本起不来。

手动重启（需管理员）：

```powershell
Stop-ScheduledTask  -TaskName PppoeWatchdog
Start-ScheduledTask -TaskName PppoeWatchdog
```

## 五、日常操作

| 想做什么 | 怎么做 |
| --- | --- |
| 看当前状态 | 双击 `check.bat` |
| 换密码 / 换连接名 | 重新双击 `setup.bat` 覆盖 |
| 立刻重连一次 | `check.bat` 看是否真断；需要的话 `rasdial 宽带连接 /disconnect` 后等守护自动重拨 |
| 临时停掉守护 | `Stop-ScheduledTask -TaskName PppoeWatchdog`（下次登录会自动再起） |
| 卸载 | 双击 `uninstall.bat` |

彻底清理运行时文件：

```powershell
Remove-Item "$env:LOCALAPPDATA\PppoeWatchdog" -Recurse -Force
```

## 六、可选优化 1：网卡省电特性

很多有线网卡默认开着几项省电功能，会让链路在空闲 / 待机时降速甚至休眠，是「莫名掉线」和「只跑到百兆」的常见来源：

| 属性 | 常见默认 | 建议 |
| --- | --- | --- |
| 环保节能（Green Ethernet） | 开启 | 关闭 |
| Gigabit Lite | 开启 | 关闭 |
| Power Saving Mode | 开启 | 关闭 |
| 网络唤醒和关机连接速度 | 10 Mbps 优先 | 不降速 |
| 快速启动（Fast Startup） | 开启 | 关闭 |

**先预览**（不改任何东西）：

```
tune-nic.bat
```

确认输出合理后，双击 **`tune-nic-apply.bat`** 写入（自动提权，链路会重新协商，可能断网几秒 —— 守护脚本会自己重拨）。

等价的命令行写法：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<脚本目录>\tune-nic.ps1" -Apply
```

脚本会先校验每个属性的合法取值，驱动不支持的项目自动跳过，不会写坏配置。

**关于只跑到 100 Mbps**：先排除物理层。最常见的原因是网线只有 4 芯能通 —— 换一根确定完好的 Cat5e / Cat6 试试。如果墙上面板到交换机那一侧本身就限速百兆，换线也没用，得找网络管理员。换个设备插同一根线对比，是最快的判断方法。

## 七、可选优化 2：开机免登录

默认情况下，开机仍然要手动输入 Windows 密码，登录后守护才会拨号。想完全无人值守就配自动登录。

**方法 A：netplwiz**

Windows 11 默认隐藏了「要使用本计算机，用户必须输入用户名和密码」复选框。先把这个注册表值改成 `0`：

```powershell
Set-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\PasswordLess\Device' `
    -Name DevicePasswordLessBuildVersion -Value 0 -Type DWord
```

然后 `Win+R` → `netplwiz`，取消勾选该复选框，填入账户密码。

**方法 B：Sysinternals Autologon（推荐）**

不用改注册表，密码以 LSA 密钥加密存进 `LSA Secrets`，比 netplwiz 的明文 `DefaultPassword` 安全。

两种方式都要注意：

- Windows Hello 的 **PIN 不能用于自动登录**，必须填账户的**真实密码**
- 自动登录意味着任何人开机都能直接进桌面，物理安全要自己权衡
- Microsoft 账户的话，「密码」指微软账户密码，不是本机 PIN

**如果觉得每次输一下密码无所谓，这步完全可以跳过** —— 「登录后自动拨号」已经省掉了手动拨号这个动作。

## 八、已知限制

- **睡眠期间不能保持在线**。只有 S0 低电量待机（Modern Standby）的机器上，睡眠会冻结 `RasMan` 维持的用户态 PPPoE 会话，会话必然断。守护脚本只能在唤醒后尽快恢复（通常 20 秒内）。想真正零中断，唯一办法是把拨号搬到常驻设备：支持 PPPoE 的路由器 / OpenWrt 软路由 / 树莓派 / 旧笔记本。注意校园网常有 MAC 绑定，且不少学校禁止私接路由器 —— 动手前先确认学校规定。
- **必须先登录 Windows 才能拨号**。PPPoE 会话由 `RasMan` 在用户会话内维护，SYSTEM 身份的服务运行在 session 0，那里没有用户的拨号上下文，拨不了。
- **密码会短暂出现在命令行**。`rasdial` 只接受命令行传参，每次重拨的几百毫秒内密码字符串存在于 `rasdial.exe` 的命令行里，同机其他进程理论上可通过 WMI 看到。单人笔记本风险很低；多用户环境要慎重。
- **探测依赖 ICMP**。如果网络封禁 ping，把 `$ProbeList` 换成能通的地址，或者自己把 `Test-Online` 改成 TCP 探测。
- **重拨会先断开**。脚本调用 `rasdial <连接名> /disconnect` 再重连。同一账号在别处登录会导致互踢，别在多台设备上同时用它。
